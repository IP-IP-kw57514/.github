<h2>先分清两件事：一个专线带多个 IP，和多条专线各一个 IP</h2>
<p>「专线含多个 IP」是同一条线路分配了若干地址，它们共享这条线路的带宽和链路质量，只是对外呈现不同地址。「多条专线各一个 IP」是物理或逻辑上彼此独立的线路，各自有独立带宽、独立故障域。</p>
<p>前者的成本低得多，因为带宽是共享的；后者的隔离度高，一条出问题不影响另一条。做分配方案之前，先确认自己手里是哪种，否则算出来的方案会错位。</p>

<h2>多个 IP 的三种用法，各有各的场合</h2>
<p>第一种是绑在设备上：每个地址固定分给一台设备，设备对外永远是那个地址。这种做法最稳，适合长期运营。第二种是绑在出口上：地址绑在网关，按规则决定哪个流量走哪个地址，设备本身不感知。</p>
<p>第三种是按需临时指定：不预先分配，用的时候指定走哪个地址。灵活性最高，但最容易乱——一段时间之后没人记得哪个地址被谁用过，而这正是账号关联风险的高发处。</p>

<h2>分配之前先定一条基线：一账号一 IP</h2>
<p>这是最稳妥的起点。一个账号长期只用固定一个地址，登录地稳定、行为一致，也便于事后追溯。做不到一账号一 IP 时，再考虑其他安排，但要知道每一次妥协都对应一份风险。</p>
<p>基线定了之后，把「账号—地址—绑定时间」写成一张表。这张表是后面所有决策的依据：加账号时看哪里有空位，出问题时查哪个地址最近有变动。</p>

<h2>账号数与 IP 数的三种关系</h2>
<p>三种关系对应三种策略，硬套某一种都会出问题。下表按常见规模给出参考，具体以业务对隔离的要求为准。</p>
<table>
<tr><th>关系</th><th>常见做法</th><th>隔离程度</th><th>适用规模</th></tr>
<tr><td>IP 多于账号</td><td>一账号一 IP，余量留作备用与替换</td><td>最高</td><td>账号少、要求严</td></tr>
<tr><td>IP 等于账号</td><td>严格一一绑定，不临时调度</td><td>高</td><td>规模稳定、长期运营</td></tr>
<tr><td>IP 少于账号</td><td>同一 IP 承载同组同质账号，分组管理</td><td>偏弱</td><td>账号多、单账号权重低</td></tr>
</table>
<p>第三种情况要特别注意「同组」的定义：放在同一地址下的账号，最好属于同一业务、同一地区、同一运营逻辑，这样即使被关联，影响范围也限于这一组，不会串到别处。</p>

<h2>同一台设备上怎么用多个地址</h2>
<p>技术上常见三种做法：一是多网卡分别绑不同地址；二是在网卡上添加多个地址，按规则决定出站源地址；三是在网关层统一做策略，设备只连网关。第三种对设备最透明，也最容易统一管理。</p>
<p>不管用哪种，都要保证「同一时刻一个连接只用一个地址」。混用会让某些请求从 A 出、某些从 B 出，外部看起来就是这个账号在两个地方同时活动，属于典型异常。</p>

<h2>别在同一个出口上做互相冲突的操作</h2>
<p>多个账号共用一条线路时，最需要克制的是操作节奏。同一时间做同样的动作、同一时间段集中登录、同时段批量修改资料，这些行为在外部看来高度一致，很容易被归为同一批。</p>
<p>建议把操作错开：不同账号的活跃时段分散、动作类型不同、频率有差异。这不是为了「绕过检测」的技巧，而是让行为本身更接近真实用户的自然状态。</p>

<h2>一份能直接用的分派记录</h2>
<p>记录至少包含五列：账号标识、绑定地址、绑定开始时间、承载设备或环境、当前状态。有条件的再加一列备注，记下这个地址历史上承载过什么。</p>
<p>那张「历史承载」列很关键。地址是可以回收再分配的，但历史上用过的痕迹不会立刻消失。知道某个地址三个月前承载过什么，能帮你避免把它分给不该分的东西。</p>

<h2>三个容易出错的地方</h2>
<p>第一是地址回收后立刻重用。旧账号的行为痕迹还在，新账号承接同一个地址，风险直接继承。建议回收后留一段空置期，或干脆不用于重要账号。第二是设备与地址交叉：换设备不换地址，或者换地址不换环境，两种都会留下痕迹。</p>
<p>第三是记录缺失。三个人各管一段，谁都不知道某个地址现在归谁，这种状态下出问题是必然的。管理多 IP 的核心不是技术，而是这张表有没有人维护。</p>

<h2>规模变化时怎么调整</h2>
<p>扩量时优先加线路而不是压缩分配。IP 少于账号的状态一旦形成，很难回到严格一一对应，因为已经混过的组合无法拆分。缩量时相反，先停止新增，把空出来的地址留作备用，不要立刻回收。</p>
<p>调整过程中最重要的是同步更新记录。规模一变就重做一次分派表，比在旧表上打补丁可靠得多。</p>

<h2>常见问答</h2>
<h3>一个专线的多个 IP 会不会被认为是同一批？</h3>
<p><strong>答：</strong>有可能。同段地址在外部看来关联度较高，是否受影响取决于平台判断维度，无法保证不被关联。</p>
<h3>账号多、IP 少，怎么降低风险？</h3>
<p><strong>答：</strong>按业务分组，让同组账号在网络身份上本就相似；同时严格分散操作节奏，避免行为同步。</p>
<h3>能不能让一台设备在不同时间用不同地址？</h3>
<p><strong>答：</strong>技术上可以，但同一账号频繁换地址本身就是异常特征，不建议对重要账号这么做。</p>
<h3>IP 用久了要不要换？</h3>
<p><strong>答：</strong>如果表现稳定，不建议主动换。稳定的登录地通常是加分项，频繁更换反而引人注意。</p>
